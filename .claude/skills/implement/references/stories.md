# Stories and tests

The detail behind step 3 of [the skill](../SKILL.md). Read it before writing the stories.

- Add a `Conformance` story that passes the spec's facts to `checkConformance` from `@package-internal/utils/storybook`, starting from `CONFORMANCE_BOX_FIELDS`, `CONFORMANCE_BOX_NONE` and `CONFORMANCE_TEXT_FIELDS`. Import the facts as `@package-specs/<component>.facts.json` (FS-06). Every fact must be mapped or ignored, and each ignored field needs a comment citing the Decision behind it.
- Write the props table in the story's `argTypes` (FS-07): a `createArgType` row for every prop in the spec, `ref` included, showing the type's name with its values as `options`, `createAdditionalTableGroups` for the native attributes, and a row in the `HTML Attributes` category for any native attribute the meta's `args` set. Give every story a comment above its export, true of what it renders.
- Don't measure contrast or re-check token values in stories. `contrast-pairs.json` checks each token pair in every theme, `Conformance` proves which tokens render in each state, and axe checks rendered text in every story. If the spec pairs two tokens with no pair in that file, stop and ask the approver. Read variants with `getConformanceAxis`, so a story needs no casts (TS-09), and pass `forcePseudoState` a selector unique to the story, because a bare `button` takes the first match across every frame and the test silently proves nothing.
