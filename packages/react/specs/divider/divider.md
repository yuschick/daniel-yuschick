# Divider

## Purpose

A section break between distinct content sections of a page, such as `<h2>` sections or `<main>` and `<footer>`. It renders a native `<hr>` as its only semantics, drawn as a line that breaks around a decorative illustration of five flowers. It's static and non-interactive.

## Anatomy

A root `<div class="divider">` laid out as `display: flex` with `align-items: center` and `gap` from Figma's root `itemSpacing`, matching Figma's horizontal, vertically centered layout (D1). It declares `inline-size: 100%`, so it fills its container in any parent layout, including a flex or grid parent that would otherwise shrink it to the flowers, with no maximum (D2). Its block size is never set: it hugs the illustration.

- **Start line:** the native `<hr class="line">`, the first child, which fills the start side (D1). It declares `border: none`, which CSS-08 allows because the `<hr>` is neither interactive nor floating, then `border-block-start: var(--dy-border-width-default) solid var(--dy-color-border-primary)`, `block-size: 0` and `flex: 1`. These four line declarations (`border: none`, `border-block-start`, `block-size: 0` and `flex: 1`) are written once, nested inside `.divider` as `& .line, &::after { … }` (CSS-12), so the two lines can't drift apart, matching Figma's `line` height and stroke (D7). The `<hr>`'s other browser defaults, such as `color` and `overflow`, have no visible effect once the border color is explicit, so they're left alone.
- **Flowers:** an `<img class="flowers" alt="">` whose `src` is the illustration's URL, an SVG file in the Divider folder (D8, D12). The empty `alt` makes it decorative, so it has no role or name. Its `block-size` is `--dy-size-component-m`, from Figma's 44px `flowers` height, and its `inline-size` is `auto`, so the width follows the SVG's viewBox ratio, as Figma's 157.14 / 44 does (D3). It never shrinks (`flex-shrink: 0`).
- **End line:** the root's `::after`, with `content: ''` plus the shared line rule above, so the two lines always match (D1).
- **Color:** both lines take their border color from Figma's `line` stroke token. Nothing has a fill, so nothing is painted behind the illustration, whose own colors are artwork (D11). The divider sits on the page, raised and sunken surfaces, the ones its contrast is verified against (D5).

There are no other elements, and no padding or margin: the reset zeroes both, including the `<hr>`'s browser `margin-inline: auto`, from its `dy.reset` layer, which sits below `dy.react` and declares the layer order itself, Figma's padding is 0, and spacing outside the Divider belongs to the consumer's layout (D6).

## API

| ...htmlAttributes | `object`, an empty remainder (D4) | -      | -       | -     | D4               |

`DividerProps` is `{ ref?: React.Ref<HTMLDivElement> }` and nothing else (D4). It extends no native attribute type, so Divider takes no `className`, `style`, `children`, `id`, `data-*` or ARIA attributes. The `...htmlAttributes` row states that empty remainder as `object` for the `/implement` API gate. Figma has no component properties.

In the props table (FS-07), the only row is `ref`, under `Component Props`. There is no `HTML Attributes` group (D4).

## Behavior and accessibility

WAI-ARIA pattern: none. Divider is not a widget, so no APG pattern applies. It exposes the ARIA `separator` role through the native `<hr>`, which is horizontal by default.
