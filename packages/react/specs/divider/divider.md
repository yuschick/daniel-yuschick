# Divider

## Purpose

A section break between distinct content sections of a page, such as `<h2>` sections or `<main>` and `<footer>`. It renders a native `<hr>` as its only semantics, drawn as a line that breaks around five floral emoji. It's static and non-interactive.

## Anatomy

A root `<div class="divider">` laid out as `display: flex` with `align-items: center` and `gap` from Figma's root `itemSpacing`, matching Figma's horizontal, vertically centered layout (D1). It declares `inline-size: 100%`, so it fills its container in any parent layout, including a flex or grid parent that would otherwise shrink it to the flowers, with no maximum (D2). Its block size is never set: it hugs the flowers.

- **Start line:** the native `<hr class="line">`, the first child, with `flex: 1` so it fills the start side (D1). It declares `border: none`, then `border-block-start: var(--dy-border-width-default) solid var(--dy-color-border-primary)`, `block-size: 0` and `flex: 1`. These line declarations are written once, in a single rule whose selector list covers both `.line` and `.divider::after`, so the two lines can't drift apart, matching Figma's `line` height and stroke (D7). The `<hr>`'s other browser defaults, such as `color` and `overflow`, have no visible effect once the border color is explicit, so they're left alone.
- **Flowers:** a `<span class="flowers" aria-hidden="true">` laid out as `display: flex` with `align-items: center` and `gap` from Figma's `flowers` `itemSpacing`. It never shrinks (`flex-shrink: 0`) or wraps. It holds five `<span>` elements, one emoji each, in this order: 🌸 (U+1F338), 🌼️ (U+1F33C U+FE0F), 🌺️ (U+1F33A U+FE0F), 🌼️ (U+1F33C U+FE0F), 🌸 (U+1F338) (D8). The flower tokens are declared once on the flowers `<span>` and inherited by the five emoji `<span>` elements, which have no class or props of their own. They are `color: var(--dy-color-text-default)` (Figma's flower fill) and a `font` shorthand of the flower weight, size, `--dy-font-line-height-none` (D3) and family. Figma's `fontStyle` maps to CSS `font-weight`, and `letter-spacing` stays unset, because Figma's value is 0. The font face is loaded by `@dy/fonts`, not by Divider.
- **End line:** the root's `::after`, with `content: ''` plus the shared line rule above, so the two lines always match (D1).
- **Color:** both lines take their border color from Figma's `line` stroke token. Nothing has a fill, so nothing is painted behind the flowers. The divider sits on the page, raised and sunken surfaces, the ones its contrast is verified against (D5).

There are no other elements, and no padding or margin: the reset zeroes both, Figma's padding is 0, and spacing outside the Divider belongs to the consumer's layout (D6).

`DividerProps` is `{ ref?: React.Ref<HTMLDivElement> }` and nothing else (D4). It extends no native attribute type, so Divider takes no `className`, `style`, `children`, `id`, `data-*` or ARIA attributes. The `...htmlAttributes` row states that empty remainder as `object` for the `/implement` API gate. Figma has no component properties.

In the props table (FS-07), the only row is `ref`, under `Component Props`. There is no `HTML Attributes` group (D4).

WAI-ARIA pattern: none. Divider is not a widget, so no APG pattern applies. It exposes the ARIA `separator` role through the native `<hr>`, which is horizontal by default.
