# Icon

## Purpose

The one icon component in the system: it renders a single glyph from `@dy/icons` at one of the shared sizes, on its own or inside another component, such as Button or Anchor. It renders a `<span>` holding the glyph's `<svg>`. It's decorative by default, and meaningful only when it's given an accessible name.

## Anatomy

A root `<span>` holding exactly one child: the `<svg>` rendered by the `icon` component (D3, D6). There are no other elements.

- **Root:** `display: inline-flex` with `vertical-align: middle`, so an icon in running text centers on the line instead of sitting on its baseline. Inside a flex parent, such as Button, `vertical-align` has no effect and the parent aligns it (D7). Its `inline-size` and `block-size` are both the component custom property `--icon-size`, one value for both axes because the root is square, which each `size-[value]` class sets to that size's icon size token. `--icon-size` is the intended name: it has no variant segment because the size classes redefine it (CSS-07), from Figma's root width and height rows (`--dy-size-icon-m` for `m`), and it never shrinks (`flex-shrink: 0`). It has no fill, border or padding: Figma's root fill is `none`, and the reset zeroes padding and margin.
- **Glyph:** the `<svg>` from `@dy/icons/react`, rendered with its own defaults: `viewBox="0 0 24 24"`, `fill="none"`, `stroke="currentColor"`, `stroke-width` 2, round caps and joins, `aria-hidden="true"` and `focusable="false"`. Icon passes a CSS Module class to it through the icon component's `className`, which `IconComponentProps` accepts because it extends `SVGAttributes`. That class sets `inline-size` and `block-size` to `100%`, so the glyph fills the root and CSS overrides the component's `1em` `width` and `height` attributes. Icon passes no other prop to the glyph. The stroke scales with the size, as a `viewBox` does (D5).
- **Color:** Icon sets no `color`. The stroke is `currentColor`, so the glyph takes the text color of whatever contains it. Figma's `--dy-color-text-default` stroke is Figma's preview color for the glyph, not a value Icon applies (D3).

| ...htmlAttributes | `SanitizedHTMLAttributes<React.HTMLAttributes<HTMLSpanElement>, keyof React.DOMAttributes<HTMLSpanElement> \| 'aria-hidden' \| 'aria-labelledby' \| 'role' \| 'tabIndex'>`, without `className` or `style`. `React.DOMAttributes` covers `children`, `dangerouslySetInnerHTML` and every `on*` event handler | -               | -       | -     | TS-01, D2, D10  |

`IconProps` extends `SanitizedHTMLAttributes` with the omitted keys passed as its second type argument, exactly as the row writes it and as Logo does, with no separate `Omit`. It has `role`, `aria-hidden`, `aria-labelledby` and `tabIndex` omitted (D2), and every key of `React.DOMAttributes<HTMLSpanElement>` omitted: `children`, `dangerouslySetInnerHTML` and all `on*` event handlers (D10), as the `...htmlAttributes` row states. `title`, `id`, `aria-describedby`, `data-*` and the other remaining attributes pass through to the root. `aria-label` stays, because it's how a consumer makes an icon meaningful.

`icon` takes the component itself (`icon={ChevronDownIcon}`), never an element, a `ReactNode` or a string name (D6). Any icon component from `@dy/icons/react` is valid, so the row lists no values. In the props table (FS-07), `size`'s Type is `Size` with `SIZES` as its options, and `icon`'s Type is `IconComponent`.

## Behavior and accessibility

WAI-ARIA pattern: none. Icon is not a widget, so no APG pattern applies. A decorative icon is hidden from assistive tech, and a named icon exposes the ARIA `img` role.

## Decisions

| ID  | Decision                                                                                                                                                                                                                                                                                                                                   | Resolves                                                                                           | Source                   |
| :-- | :----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | :------------------------------------------------------------------------------------------------- | :----------------------- |
| D1  | `size` uses the shared `Size` (`xs` to `xl`) with the registry default `m`. Figma's `2xl` variant was removed and its default set to `m` in Figma on 2026-11-10, at Daniel's request, and the facts confirm it. `--dy-size-icon-2xl` stays in `@dy/tokens`, unused by Icon. This rather than adding `2xl` to `Size` or a second size scale | -                                                                                                  | Daniel, PROP-02, PROP-08 |
| D2  | Icon is decorative by default. A consumer makes it meaningful with the native `aria-label` attribute, which switches the root to `role="img"` with that name and drops `aria-hidden`. `role`, `aria-hidden`, `aria-labelledby`, `tabIndex` and `children` are excluded at the type level, as are `className` and `style`                   | -                                                                                                  | Daniel, A11Y-04, TS-01   |
| D3  | The root is a `<span>` wrapping the glyph's `<svg>`, matching Figma's frame. Icon sets no color: the glyph's `currentColor` stroke inherits the parent's text color, and Figma's text/default stroke binding is only Figma's preview color                                                                                                 | -                                                                                                  | Daniel                   |
| D4  | The role and name go on the root `<span>`, with `ref` and consumer attributes. The inner `<svg>` always keeps `aria-hidden="true"` and `focusable="false"`                                                                                                                                                                                 | -                                                                                                  | Daniel                   |
| D5  | The glyph instance and vector sizes are SVG geometry, not CSS values: the `<svg>` fills the root at `100%`, so its size is the root's icon size token, and the vector sizes are path data in the 24×24 `viewBox` from `@dy/icons`                                                                                                          | root/0:Glyph width, root/0:Glyph height, root/0:Glyph/0:Vector width, root/0:Glyph/0:Vector height | Daniel                   |
