# Anchor

## Purpose

Every control that navigates and carries a text label, optionally with one decorative icon before or after it. It renders a native `<a href>` in one of two forms: the default, styled like Button, or `variant="inline"`, recolored text inside a run of prose. `intent` communicates meaning and `emphasis` communicates priority within a screen region.

## Anatomy

An `<a>` containing, in order: an icon slot `<span>` for `iconLeading` when it's set, one internal `<span>` that wraps `children`, and an icon slot `<span>` for `iconTrailing` when it's set. At most one icon renders (D23). Each icon slot is an Anchor-owned `<span>` with `aria-hidden="true"` that holds one `Icon` (D25). The `Icon` hides itself, because an Icon with no `aria-label` renders `aria-hidden="true"` (Icon D8), so the slot's `aria-hidden` exists to keep the inline form's generated word joiner out of the accessible name, and the icon stays hidden even where a browser drops `aria-hidden` on a `display: contents` element. Only when D12 applies, a visually hidden `<span>` holds the appended text, inside the label `<span>`. The text begins with a space, held inside the hidden `<span>` so nothing visible is added (D19). Both forms render this same structure (D15, D25), so `Anchor.tsx` has one template path.

The default form is `inline-flex`, centered on both axes as Figma's layout shows, including when a tall label makes it grow, so an icon stays vertically centered beside a wrapped label. Its icon slot is `display: contents`, so the `Icon` itself is the flex item, and Figma's `itemSpacing` (`--dy-space-xs`) separates it from the label as `column-gap` (D20, D25). The icon keeps its fixed size through the Icon component's own `flex-shrink: 0`, so Anchor sets no shrink rule (D24). Labels wrap, centered. `max-inline-size: 100%` caps it and `overflow-wrap: anywhere` on the label breaks long unbroken words. `text-decoration: none` removes the native underline (D7). Figma's `fontStyle` maps to CSS `font-weight`, and `letterSpacing` stays unset because Figma's value is 0. The focus ring is the anchor's own `outline`, offset from the border edge; Figma's Focus ring radius row is met by the outline following the anchor's `border-radius` (D8).

The inline form is `display: inline`, so it wraps across lines with the sentence. It sets no typography: every font property inherits from the surrounding text, and the Figma tokens table's `fontFamily`, `fontStyle`, `fontSize` rows, which Figma needs only to draw it, apply to the default form alone (D3). It has no fill, radius, minimum height, inline padding or border (D3, D14). Its only spacing is the invisible block padding from D10, which doesn't change line height or surrounding text, and the icon gap below. The internal label `<span>` is unstyled there.

On the inline form the icon slot stays an inline `<span>`. Figma's inline `itemSpacing` (`--dy-space-2xs`) becomes `margin-inline-start` on a trailing slot and `margin-inline-end` on a leading slot, because `column-gap` doesn't apply to inline content. On the side facing the label, the slot has a CSS-generated U+2060 word joiner (`::before` on a trailing slot, `::after` on a leading slot), and the slot sets `white-space: nowrap`, so the icon never wraps onto a line by itself and stays with the adjacent word (D25, D27). The word joiner prevents a break where the label's text meets the slot, and `nowrap` prevents the break that Chromium allows inside the slot, right after the `inline-flex` Icon; both are needed. The word joiner is zero-width, and the slot's `aria-hidden` keeps it out of the accessible name. The icon isn't underlined: the margin carries no text decoration, and the `inline-flex` Icon is an atomic inline that an ancestor's underline doesn't reach. The icon is 1em square, so it scales with the inherited `font-size`, through Icon's `size="inherit"` (D26). 1em has no token, by design (D26).

| Item                                                                                                | Figma | Source |
| :-------------------------------------------------------------------------------------------------- | :---- | :----- |
| `state` as a prop; it maps to CSS pseudo-classes                                                    | state | D1     |
| Icon-only anchors                                                                                   | -     | D20    |
| A leading and a trailing icon on the same anchor                                                    | -     | D23    |
| Icon props that accept an `<Icon>` element or any other `ReactNode`, or a label on an Anchor's icon | -     | D22    |
| Changing Icon in the Anchor build; Icon's `size="inherit"` is already on `main`                     | -     | D26    |
| Polymorphism, `as`, `asChild` or client-side routing such as `next/link`                            | -     | D11    |

| Dark mode values; only the Light tokens exist so far                                                | -     | D9     |

| D7  | The default form has no underline. The inline form uses the `underline` keyword, which has no token, with thickness from `--dy-border-width-default` and `--dy-border-width-focus`, accepting that this stretches the focus token's stated purpose.                                                                                                                                                                                                                                                                                                                                                                               | root/1:Anchor textDecoration               | Daniel               |
| D8  | The focus ring's `outline-offset` is `--dy-space-2xs` on both forms, measured from the border edge. For inline this is deliberately 4px rather than Figma's 2px, since no 2px space token exists. Figma's focus ring radius is met by the outline following the anchor's radius.                                                                                                                                                                                                                                                                                                                                                  | root/3:Focus ring x, root/3:Focus ring y   | Daniel               |
| D9  | The default form adopts Button's settled choices: heights as `min-block-size`, state colors animating with `fast` and `standard`, no consumer `className` or `style`, forced-colors browser defaults and its contrast measurement. Dark mode contrast isn't verified until a dark theme exists in the tokens. That is a named exemption from A11Y-08, to revisit when the dark tokens land; this spec is the record, with no separate tracking, and the Anchor build may merge with dark contrast unverified, like Button and Logo.                                                                                               | -                                          | Daniel               |
| D10 | The inline form reaches a 24px target height through invisible block padding, which doesn't change line height or prose. A pseudo-element was rejected because on a wrapped link it spans whole lines of neighboring text, while padding extends each line only by a few pixels. On `:focus-visible` the padding is 0, so the focus ring is a true 4px on every side. Width under 24px and overlap in very tight line heights rely on WCAG 2.5.8's inline exception, a named reading of A11Y-09.                                                                                                                                  | -                                          | Daniel, A11Y-09      |
| D11 | Anchor renders only a native `<a>` with a required `href`. Internal links do a full page load until client-side routing gets its own spec.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                        | -                                          | Daniel, A11Y-03      |
| D12 | Anchor appends hardcoded English for new tabs and downloads, `(opens in new tab)` and `(downloads file)`, with download taking precedence. `aria-label` or `aria-labelledby` replaces it, which is how applications override it, leaving the consumer responsible for the visible text and the cue, documented in a story rather than enforced. No i18n work is included, and the hidden text carries no `lang` attribute, an accepted gap against WCAG 3.1.2 on non-English pages, since the site is English today.                                                                                                              | -                                          | Daniel               |
| D13 | Anchor has no disabled state, and `aria-disabled` is removed from its type. An unavailable destination shouldn't render as a link.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                | -                                          | Daniel               |
| D14 | The inline form has no border, a named exception to CSS-08, because a transparent side border would shift prose. In forced colors, link color and the underline keep it identifiable.                                                                                                                                                                                                                                                                                                                                                                                                                                             | -                                          | Daniel, A11Y-08      |
| D15 | Both forms render one structure, with the label `<span>` unstyled on the inline form, so the template has one path.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                               | -                                          | Daniel, RX-09        |
| D16 | Both forms set `position: relative` on the `<a>` so the visually hidden text stays contained to the link.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                         | -                                          | Daniel               |

This is the approved reading of RX-10 alongside RX-09.                                                                                                                                                                                                                                                                                                                                                                                                                                 | -                                          | Daniel, RX-09, RX-10 |
| D18 | `children` stays any node, like Button, so label markup and hidden text work. A label with no name is left to required `children`, axe on real usage and review.                                                                                                                                                                                                                                                                                                                                                                                                                                                                  | -                                          | Daniel, A11Y-04      |
| D19 | The space before the appended text sits inside the visually hidden `<span>`, so an inline link followed by punctuation shows no underlined gap and the prose doesn't move. The accessible name is unchanged.                                                                                                                                                                                                                                                                                                                                                                                                                      | -                                          | Daniel, A11Y-04      |
| D20 | Icons are in scope on both forms now that the shared Icon exists, mirroring Button's D34: an optional leading or trailing icon beside the label. The default form separates it with Figma's `itemSpacing` (`--dy-space-xs`) as `column-gap`, and the inline form with `--dy-space-2xs` (D25). Icon-only anchors stay out of scope. Supersedes D5 and D6.                                                                                                                                                                                                                                                                          | root/0:Icon, root/2:Icon, root itemSpacing | Daniel               |
| D21 | The icon props keep Figma's names, `iconLeading` and `iconTrailing`, as Button's D35: a deliberate exception to PROP-07's `[base]Start` and `[base]End` until PROP-07 is changed to match in its own PR.                                                                                                                                                                                                                                                                                                                                                                                                                          | -                                          | Daniel, PROP-07      |
| D22 | `iconLeading` and `iconTrailing` take an `IconComponent` from `@dy/icons/react`, such as `ArrowUpRightIcon`, never a `ReactNode`, as Button's D36 and the Figma description state. Anchor renders the Icon itself, so it controls the icon's size, color and accessibility. This deviates from PROP-07's `ReactNode` type. An Anchor's icon is always decorative: the label names the link.                                                                                                                                                                                                                                       | -                                          | Daniel, A11Y-04      |
| D23 | An Anchor has at most one icon, on either form, as the Figma description states. Each icon prop is `never` when the other is set, so passing both fails type-checking, with no runtime guard or precedence, as Button's D37.                                                                                                                                                                                                                                                                                                                                                                                                      | -                                          | Daniel, TS-08        |
| D24 | On the default form, icon sizes match Button's D38: Anchor `s` uses Icon `s`, and Anchor `m` and `l` use Icon `l`, so an Anchor and a Button side by side match. The icon inherits the foreground color through `currentColor` and keeps its size through Icon's own `flex-shrink: 0`. The icons are hidden in every Figma variant, so this decision, not the facts, is the source.                                                                                                                                                                                                                                               | -                                          | Daniel               |
| D25 | Amended by D27. Each icon sits in an Anchor-owned `<span>` slot with `aria-hidden="true"`, on both forms, so the template has one path (D15). On the default form the slot is `display: contents`. On the inline form it's an inline `<span>` with `--dy-space-2xs` as its inline margin toward the label, and a CSS-generated U+2060 word joiner on that side, so the icon never wraps onto a line by itself. A wrapping icon and `white-space: nowrap` on the whole link were rejected, because the first contradicts Figma and the second can overflow narrow containers (WCAG 1.4.10).                                        | -                                          | Daniel, A11Y-04      |
| D26 | On the inline form the icon is 1em square, so it scales with the inherited `font-size`, as the Figma description states. Icon has only the rem-based token sizes `xs` to `xl` and accepts no `className` or `style`, so an em-relative size was added to Icon through its own spec PR and build first: Icon's `size="inherit"` (Icon D11, #122 and #124), which `iconProps` passes on the inline form. Overriding Icon's CSS from Anchor, and a fixed token size, were rejected.                                                                                                                                                  | -                                          | Daniel               |
| D27 | On the inline form the icon slot also sets `white-space: nowrap`. In Chromium, D25's word joiner alone keeps a trailing icon with its word but not a leading one, because Chromium allows a line break right after the `inline-flex` Icon even when a word joiner follows. The build's story that narrows the text to its longest word fails with either the word joiner or `nowrap` removed, so both are required. `nowrap` covers only the slot, which holds the icon and the word joiner, so the label still wraps and nothing can overflow (WCAG 1.4.10), unlike the `nowrap` on the whole link that D25 rejected. Amends D25 | -                                          | Daniel               |
